WORKFLOW ARCHITECTURE
=====================

Purpose
-------
compile.bat turns one or more Markdown or plain-text notes into a PDF using
Pandoc, two ordered Lua filters in config\, and XeLaTeX. Normalization does not
modify Markdown/TXT inputs; user-authored Python code can write files it
explicitly opens. The first input controls the output directory, PDF basename,
and working directory; later inputs contribute content in the order supplied.

Recommended folder layout
-------------------------
    tool-root\
        compile.bat
        README.md
        config\
            custom.tex
            markdown-normalizer.lua
            code-fence-runner.lua
        manual\
            FILTER_FEATURE_REGRESSION.txt
            FILTER_FEATURE_REGRESSION_PART2.txt
            CONTRIBUTING_AND_VERSIONING.txt
            INSTALL_AND_USE.txt
            CODE_FENCE_RUNNER_ARCHITECTURE.txt
            MARKDOWN_NORMALIZER_ARCHITECTURE.txt
            WORKFLOW_ARCHITECTURE.txt
            WORKFLOW_ASSESSMENT.txt
        md2pdf_cache\                    (created as needed; disposable)
        your own input .md/.txt files and PDFs (wherever convenient)

Keep compile.bat at the root and the three configuration files under config\.
The manual\ folder is only for workflow documentation and its regression
fixture; user input files may live anywhere. The output PDF stays beside the
first input, not in config\. The cache is rooted beside compile.bat so generated
cache files do not mix with source notes.

Requirements
------------
- Pandoc with Lua-filter support.
- XeLaTeX (XeTeX/fontspec is required by the template).
- Python for Python fences. compile.bat sets PYTHON=py for the Python launcher;
  config\code-fence-runner.lua also accepts a PYTHON environment override when used directly.
- Python packages are not installed by this workflow. Install every non-standard-
  library package imported by a Python fence into the exact interpreter selected
  by PYTHON before compiling (for example, `py -m pip install matplotlib`).
  Python fences run with the interpreter and packages already available; an
  unavailable import is a Python execution error, not an automatic installation.
- The packages, fonts, and optional extras described in config\custom.tex.

Running the compiler
--------------------
Pass one or more quoted input paths to compile.bat. Every path is validated
before the build starts. The output is <first-input-basename>.pdf beside the
first input. Temporary .tex, PDF, log, and auxiliary files are created in a
unique directory under %TEMP%; that directory is removed after success or
failure. The existing destination PDF is preserved until the new PDF has been
built and copied successfully.

compile.bat changes the current directory to the first input's directory.
Consequently, relative image/dependency paths are resolved from there, including
paths mentioned by later input files. Supply absolute paths or keep referenced
files beside the first input when combining notes from different folders.

Pipeline and ordering
---------------------
1. compile.bat validates inputs and companion files, then invokes Pandoc with
   markdown+yaml_metadata_block, --citeproc, and the custom template.
2. config\markdown-normalizer.lua is the first Lua filter. For an all-Markdown/TXT input set,
   it reads each original file, cleans and reparses it, joins the parsed blocks
   in argument order, merges cleaned YAML metadata, and overlays Pandoc's
   aggregate metadata (including command-line metadata). If any input is not
   cleanable, is stdin, or cannot be reopened, it retains Pandoc's original
   parse and applies AST repairs only. It never writes to the source files.
3. config\markdown-normalizer.lua runs its ordered text-cleaning passes, AST passes, and
   finalization. Among other things, it normalizes supported pasted LaTeX,
   repairs selected math and Unicode cases, collects preamble commands, handles
   images/tables, and reports notable changes on stderr. Citeproc is run after
   reparsing when bibliography or references metadata is present.
4. config\code-fence-runner.lua walks the normalized combined AST once. Recognized executable
   code blocks therefore run in source order across all input files. LaTeX/TeX
   fences are rendered rather than executed. Preambles rescued from full
   LaTeX code blocks are prepended to the collected header-includes.
5. Pandoc writes temporary LaTeX. XeLaTeX runs in the temporary build folder
   and repeats up to three times when its log requests another reference pass.
   The completed PDF is copied beside the first input; temporary build files
   are then removed. The Python cache is separate and persists in md2pdf_cache
   beside compile.bat.

The order of the two Lua filters is intentional: config\code-fence-runner.lua
must see the combined, normalized AST produced by config\markdown-normalizer.lua.
Keep config\markdown-normalizer.lua first.

Inputs, metadata, and citations
-------------------------------
The documented/common inputs are .md, .markdown, and .txt. For these types,
the custom reader enables YAML metadata, raw TeX, dollar and single-backslash
math, fenced Divs, pipe tables, and bare-URL autolinking while disabling
Markdown subscript/superscript parsing. Standard Markdown lists and Pandoc task
lists are recognized: `- item` is a bullet, and `- [ ] item` / `- [x] item`
are task-list entries. A bare `[ ] item` without the list marker is paragraph
text, not a list. This distinction is covered in manual\INSTALL_AND_USE.txt and
manual\FILTER_FEATURE_REGRESSION.txt. Multiple files retain command-line content
order. The first cleaned YAML value is retained and later YAML maps fill
missing keys; Pandoc's aggregate metadata is overlaid afterward, so conflicting
values follow Pandoc's multi-input precedence and command-line overrides.
title, author, and date extracted from a pasted full LaTeX document are
fallback values only and do not replace existing metadata.

The compiler enables Pandoc citeproc. Bibliography and CSL metadata should use
Pandoc's citeproc conventions. The template supplies CSL bibliography
definitions. Its \cite command is customized for figure labels and bracketed
keys, so raw natbib/biblatex citation workflows are not supported. Citation
cleanup in markdown-normalizer.lua targets known AI-generated artifacts; it is not a
general citation parser.

Text normalization and LaTeX
----------------------------
config\markdown-normalizer.lua's text passes act before reparsing and protect fenced code,
indented code, code spans, and selected verbatim environments from prose-only
rewrites. They clean selected invisible/space characters, AI citation markers,
tracking parameters, and HTML leftovers; repair selected math delimiters;
normalize pipe tables; collect selected preamble commands; and convert
supported theorem/proof-like environments into Markdown-parsed Divs before
restoring their LaTeX wrappers.

Selected preamble commands are moved to header-includes. Packages already
provided or conditionally managed by config\custom.tex are skipped to avoid
option clashes. A full-document LaTeX fence also recovers supported command
definitions and settings from the source preamble: command definitions,
document commands, math operators/paired delimiters, new theorem/environment
definitions, Unicode declarations, TikZ/PGF library and style settings, and
theorem style. Commented commands are ignored; unrecognized preamble content
is discarded. See config\code-fence-runner.lua's USER GUIDE for the exact command list.
The template at config\custom.tex is XeLaTeX-specific and defines page layout,
fonts, math and Unicode mappings, tables, code, figures, links, citations, and
optional packages. See its opening FEATURES and LIMITATIONS comments for exact
package, font, and symbol caveats. Missing optional packages may leave their
commands undefined; missing glyphs may be blank and reported in the XeLaTeX log.

Fenced-code attributes
----------------------
Recognized executable languages are Python (python, py, python3, py3) and
LaTeX/TeX (latex, tex). Attributes use Pandoc fenced-code syntax, for example:

    ```{.python run=new show=false maxlines=20}
    print("fresh execution")
    ```

Executable fence attributes:
- run=false leaves a recognized block as an ordinary code listing.
- An omitted run attribute and run=true both execute normally when needed and
  use the cache when the entry is valid. run=true is not a cache bypass.
- run=new forces this execution to run, then replaces/refreshes the cache entry
  on success. cache=false has the same cache-bypass behavior. Failed runs are
  not cached.
- show=false hides source; output=false hides captured stdout; error=false hides
  the rendered error while the error is still written to the console.
- maxlines=N limits displayed stdout. figures=false suppresses embedding Python
  figures but does not suppress files explicitly saved by the user's code.
- deps="a.csv,b.npy" adds files whose content hashes participate in the cache
  key. img="figure.png" is a legacy Python fallback when no captured figure is
  available.

Python execution, figures, and cache
------------------------------------
Python code is run as a script in the first input's directory. The code file
and generated wrapper live in the cache directory, while __file__ is presented
as <working-directory>/__md2pdf_block__.py and the working directory is added
to sys.path. stdin is redirected from the null device to prevent interactive
reads from hanging the build. stdout is displayed in the document; stderr is
also sent to the console. A failed execution produces a traceback/error block
and does not stop Pandoc from rendering the rest of the document.

Matplotlib figures are automatically collected for the PDF. Figures explicitly
saved by the code remain at their requested paths; a PDF-compatible copy is
also captured when enabled. Unsaved figures are captured on show/exit. Figure
files are stored in the cache and embedded in the generated PDF. Non-Python
languages can be added in config\code-fence-runner.lua's language registry using its template
contract; automatic dependency tracking is currently Python-only.

Cache keys include code, language, executable, runtime/package fingerprint,
runner-template fingerprint, figure options, explicit dependency contents, and
the cache schema. Successful Python runs record eligible files read and
workspace-local side effects written. A valid cache hit restores missing
side-effect outputs and reuses captured output/figures. The cache uses a
200-entry LRU index; deleting md2pdf_cache is safe and only causes reruns.

The automatic Python audit hook is best-effort: it tracks file-open activity,
not arbitrary environment variables, network results, or every possible
external data source. Use deps= for dependencies that cannot be discovered
reliably. Cache hits cannot reflect untracked inputs. Runtime fingerprinting
failure disables cache reuse for that execution.

Failures, limits, and troubleshooting
-------------------------------------
- A missing input or companion filter/template fails before conversion.
- Pandoc failures and XeLaTeX failures are reported in the console. XeLaTeX
  output that exists despite logged errors may still be delivered with warnings.
- If replacing the destination PDF fails, close it in any PDF viewer and check
  directory permissions; the prior PDF is not deleted before the copy attempt.
- The compiler pauses before returning, so it is designed for interactive use.
- Relative assets for all inputs resolve from the first input's directory.
- Only supported local image types (PNG, JPG/JPEG, PDF) are embedded by the
  filter. Remote, missing, or unsupported images are dropped with a warning.
- Python input, environment variables, network calls, and external state are
  not universally cache-tracked. Use run=new/cache=false for a deliberate rerun.
- Python dependencies are not bootstrapped or installed during a build. Install
  required third-party modules into the selected Python interpreter beforehand;
  for example, use `py -m pip install <package>` when PYTHON is `py`.
- Pandoc, Python, TeX packages, and fonts vary by machine; consult the messages
  emitted by [markdown-normalizer], [code-fence-runner], Pandoc, and XeLaTeX before diagnosing
  a blank glyph or incomplete PDF.

Testing and maintenance
-----------------------
The checked-in broad regression input exercises the normal end-to-end path:

       .\compile.bat "manual\FILTER_FEATURE_REGRESSION.txt"

Run that command from the tool root. The generated PDF is beside the fixture in
manual\. It intentionally includes a controlled Python failure and expected
cleanup warnings; those are not Pandoc/XeLaTeX build failures. Its companion
beginner setup guide is manual\INSTALL_AND_USE.txt. The fixture is compiled by
itself with compile.bat and covers Markdown/task-list syntax, LaTeX preamble
recovery, Python execution/cache/failure behavior, citations, and figure
embedding. It also contrasts default cached Python, run=new fresh execution,
and run=false source-only rendering with an optional NumPy/Matplotlib
coin-flip running-average probability graph.

The separate multi-input check uses both regression inputs in one invocation:

       .\compile.bat "manual\FILTER_FEATURE_REGRESSION.txt" "manual\FILTER_FEATURE_REGRESSION_PART2.txt"

The first input determines the PDF path. Verify the four
MULTI_INPUT_PART_* markers appear exactly once in the PDF, ordered as documented
in FILTER_FEATURE_REGRESSION.txt. This checks concatenation order and one
rendered output per Python fence; it does not rerun each fence for every input.

1. Check filter syntax/loading without building a PDF:

       pandoc --from=markdown --to=native --lua-filter=config\markdown-normalizer.lua --lua-filter=config\code-fence-runner.lua

   Provide a small Markdown document on stdin or as an input file.
2. Test the compiler with a disposable .md containing metadata, math, a table,
   an image, citations, and a code fence. Verify the PDF and inspect stderr and
   the temporary LaTeX log before cleanup.
3. Test cache behavior in an isolated MD2PDF_CACHE directory with a small
   Python block that writes an execution counter: omitted run/run=true should
   execute on a cold cache and hit on an unchanged run; run=new and cache=false
   should each execute again and refresh the same cache entry.
4. Test failure paths with a missing input, a Python exception, and a controlled
   destination-PDF copy failure; confirm source files and any pre-existing PDF
   remain intact.
5. Keep config\markdown-normalizer.lua's TEXT_PASSES, AST_PASSES, and FINALIZE_STEPS in their
   documented order. Add each new rule/handler to its named ordered registry,
   keep mutable state in its State table, and preserve the config\markdown-normalizer.lua
   then config\code-fence-runner.lua filter order in compile.bat. Keep the two package skip lists
   aligned with packages managed by config\custom.tex.

Extension points
----------------
- Add prose cleanup in config\markdown-normalizer.lua's SCRUB_RULES or whole-text handling in
  TEXT_PASSES; protect code with the existing literal/fence masking helpers.
- Add AST repairs in the matching handler and AST_PASSES entry; report notable
  loss or changes with the filter's warn() function.
- Add executable languages in config\code-fence-runner.lua's register{} table and provide a
  template using the documented @@CODE@@, @@PREFIX@@, @@DEPS@@, @@WRITES@@,
  and @@FIGURES@@ tokens. Use run_exec's cache and renderer contracts rather
  than adding language-specific dispatch to compile.bat.
- Adjust typography, packages, Pandoc variables, or Unicode mappings in
  config\custom.tex, keeping its documented limitations accurate.
- Update this document whenever invocation, ordering, cache semantics,
  metadata handling, output placement, or supported contracts change.
